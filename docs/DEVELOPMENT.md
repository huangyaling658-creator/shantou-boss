## 0. 一句话现状

闪投 = BOSS 直聘 Chrome MV3 扩展（侧边栏）。两模式：
- **海投（position）**：真人链路版——主页起步 → 驱动搜索框搜词 → 选城筛选 → **滚动读卡**，一次滚动=一个行为，与精投共用全局行为闸。
- **精投（company）**：锁定几家公司，进**每家公司招聘页读 DOM 卡**收岗位，全局行为节流。

全链路可跑：搜索召回 → 就地生成招呼语 → 投递。核心精力都花在**精投的可靠性 + 节流**上。

`secrets.js`（通义千问 key）走 `.gitignore`，各人 `cp src/shared/secrets.example.js src/shared/secrets.js` 填自己的。

## 1. 精投现在怎么工作（重点，最近全重写过）

**入口**：`service-worker.js` 的 `augmentFromCompanyPages(merged, config, onProgress)`。

### 1.1 搜索时长与行为预算
- 设置齿轮里有「搜索时长」拉杆：**3~30 分钟**，存 `chrome.storage['jt:searchMinutes']`，默认 5。
- 后台：`taskTimeoutMs = 分钟×60000`（时间硬上限）；`actionsBudget = 分钟×12`（`ACTIONS_PER_MINUTE`，每分钟 12 个行为，因为全局每 ~5 秒一个行为；5 分钟 = 60 个，用户 2026-10-06 定）。

### 1.2 全局行为闸（turnGate）——节流核心
- **全局每 4~6 秒随机才放行一个「翻页行为」**（读一页 = 一个行为，用户 2026-10-06 由 4~8 调整为 4~6），用「预约下一个时间槽」(`nextTurnAt`) 保证并发的页面依次拿槽（先到先得≈轮流派发），不会一起放行。
- 任意时刻只有一个请求在飞、均匀无突刺，这是躲限流(code:37)的关键。
- `actionsDone` 每放行一次 +1；进度条 % = `actionsDone / actionsBudget`（面板不显示数字，只显示 %）。
- 到 `taskDeadline`（时间上限）或全部收完就停。

### 1.3 一条龙 per 标签（onePass）
每家公司一个后台标签，一条龙跑完：
1. **定位 brandId**（没有 override 时）：开搜索页搜「公司名」，`READ_BRAND_DOM` 从结果页 DOM 读。
   - **只搜公司名、不带职位/城市筛选**（否则小公司加筛选后搜不出几条，页面被「推荐其他公司」占满，定位投歪）。
   - **按公司名匹配**：取第一张「公司名含搜寻名/别名」的卡的 `/gongsi/{brandId}` 链接（排除底部推荐的别家）。退：第一张有公司链接的卡 → 全页投票兜底。
   - 依次试 `[搜寻名, 公司名, ...别名]`，每个读 3 次给异步渲染时间。
2. **开全新公司页标签**：读到 brandId 后**关搜索标签、`chrome.tabs.create` 开新标签**进 `/gongsi/job/{brandId}.html`。
   - ⚠️ 不能用 `tabs.update` 同标签导航——BOSS 是 SPA，同源导航 `waitForTabComplete` 会立刻看到旧的 complete 就返回，公司页没真加载完 → 只收到 1 页。这是踩过的坑。
3. **收职位**：驱动公司页搜索框打岗位词 → `COMPANY_DOM_PAGE` 一页页读卡（每页前过 `turnGate`）。

### 1.4 重做（三重保障，行为版）
`processCompany` 外层：一轮跑完若**这轮用的行为数 ≤ 4**（太快，多半只收到 1 页/定位错）→ **重做**；重做时 `actionsBudget += 10`（给重做腾预算）；**每家最多重做 3 遍**。重做会重新定位，能救偶发的定位歪/渲染慢。

### 1.5 开页节流 + 关标签（模块级共享，精投/海投同一套）
- `acquireOpenSlot()`：每开一个分页全局隔 1~2 秒随机（预约槽，并发也真错开）。精投开公司标签、海投开城标签都过这同一条闸。
- `closeTabLater(tabId)`：用完的标签**延迟 1~3 秒随机再删**，且**后台异步不阻塞**（下一个不等删完就开始）。
- 间隔常量集中在 `constants.js`：`TAB_OPEN_MIN/MAX_MS`(1000/2000)、`TAB_CLOSE_MIN/MAX_MS`(1000/3000)。
- **长期原则（用户定的）：这类行为要模仿人类**——人不会同一秒连开 5 个分页、不会用完瞬间关掉、每一步操作前都会看一眼页面。以后加分页/导航/点击类行为，一律走共享闸 + 随机区间停顿，不写死固定值。

### 1.6 手动覆盖（异常公司那行）
结果页「搜索过程与结果」折叠区里，异常/没定位到的公司下方有一行 `搜寻名：xxx [更改] [改网址]`（都要密码 **012026**）：
- **更改** → 改**搜寻名**（`S.searchОverrides[公司名]→中文名`，存 `jt:searchOverrides`）。后台定位优先用它。
- **改网址** → 贴这家 BOSS 公司主页网址，抽出 brandId（`S.brandOverrides`，存 `jt:brandOverrides`）。**最优先、直接用、跳过定位**（救 vivo/OPPO 这种搜出来第一条是乱公司的）。

### 1.7 公司库的「显示名 vs 搜寻名」
`src/data/companies.js`：`n`=显示名（给用户看，品牌名）；`s`=搜寻名（后台定位用，必须 BOSS 上收得住）；`a`=别名。目前只给 **智谱AI(s=智谱华章)**、**DeepSeek(s=深度求索)** 配了 `s`。**别的公司没配，别乱改没反馈过的公司。**

## 2. 海投现在怎么工作（2026-10-06 重做：真人链路版）

海投 v2 复现用户亲自演示的真人操作链路，入口是 SW 的 `runHaitouScroll(config, merged, onProgress)`：

1. **每城一个标签**（最多 `HAITOU_MAX_TABS: 5` 并行，用户定的上限），**先从 BOSS 主页起步**（不直接拼搜索 URL 导航）。开标签前过模块级开页闸 `acquireOpenSlot()`——5 个城每隔 1~2 秒随机轮流开，不一窝蜂齐开；采完经 `closeTabLater()` 隔 1~3 秒随机再关（均与精投共用，见 §1.5）。
   - 各步骤停顿全是**随机区间**（模仿人类，不写死）：主页加载后 800~1800ms 看一眼、换词回主页 900~1600ms、搜索框驱动后 1000~2000ms、筛选页导航后 1200~2200ms、激活标签后滚动前 250~600ms。
2. **驱动首页搜索框搜职位词**（`DRIVE_HOME_SEARCH`，collector.driveHomeSearch）；选了多个词就回主页挨个搜，**每词每城各一轮**，量 = 词×城×滚动采集。
3. **选城市/筛选**：导航到带 city/筛选参数的结果页 URL（= 人点筛选器的等效；搜索框驱动失败时这步也是兜底入口）。
4. **滚动读卡**（`COLLECT_ONE_SCROLL` 单步，collector.collectOneScroll）：读新增卡 → 滚一屏 → 等渲染再读。**一次滚动 = 一个行为**，过模块级全局闸 `acquireTurnGlobal(4000, 6000)`——与精投同一条槽链、**同为 4~6 秒随机**（用户 2026-10-06 定；`HAITOU_TURN_GATE_MIN/MAX_MS` 与 `TURN_GATE_MIN/MAX_MS` 各自独立可调）。
   - 布置阶段的**每个动作都过开页闸 `acquireOpenSlot()` 排队**（用户两次实测反馈布置太快）：开分页、回主页导航、驱动搜索框（填词+点搜索）、带 city/筛选参数的结果页 URL 导航——每个都是 1~2 秒随机一个行为，多分页轮流布置。
   - 新版结果页是「左卡右 JD」双栏，左栏滚动加载；滚动懒加载**只在前台标签触发**（后台被 Chrome 节流，老代码注释实证过），所以每步滚动前把标签**轮换激活**——人一次也只能看一个标签。跑海投时几个标签会轮流跳前台，正常现象。
   - **字段补全**：DOM 卡只有卡片字段，读卡后拿 jobId 查嗅探器的 `JOBLIST_META` 补接口级字段（HR 活跃度、公司规模、融资阶段等）——行为是人的，字段是接口级的。
   - **薪资防乱码**（2026-10-06 用户实测发现）：BOSS 薪资数字用自定义字体渲染，DOM 读出来是私有区字符（面板显示 □□□-□□□元/天）。collector 用 `GARBLE_RE`（私有区 U+E000~F8FF + U+FFFD）检测，乱码就丢弃 DOM 值、用嗅探器从接口 JSON 抓的 `salaryDesc` 兜底。
5. **行为预算 = 搜索时长(分钟)×12，按「词×城」单元平分**（用户口径）；连续 3 次滚动 0 新增（滚到底）/ 预算完 / 时间到，任一即停。
6. 进度复用精投的 `actionsDone/actionsBudget` 口径，面板 % 显示同源。

旧的「接口复放 + 多城各自本地 sleep」路径（collectOnCity）已删除——那是突刺风险的来源，也是「量被 150/词封顶卡死」的来源。`COLLECT_PAGES` 路由和 `collectPages` 保留（精投定位、DOM 兜底仍在用）。

## 3. 结果页 / UI 现状

- **投递模式**：海投 / 精投 切换。
- **搜索时长**：齿轮 → 设置抽屉 → 拉杆（3~30 分钟）。
- **开始搜索**：单按钮（之前试过浅搜/深搜双按钮，已撤）。进度条 % = 行为/预算，文字 `X% · 约还需 N 分钟 · 已收 M 个`，带实时计时「用时 M:SS」，完成显示「本次搜索用时」。
- **登录失效检测**：精投若「已定位的公司几乎都只 1 页」→ 顶部橙条提示重新登录 BOSS（`maybeWarnLogin`）。本质是没登录时公司页只给默认几个。
- **搜索过程与结果**（折叠区，`#search-detail-sec`）：搜索中默认展开、结束自动收起。内含：
  - **每家公司状态清单**（`renderCompanyStatus`）：定位中 • / 搜职位中 •(带实时页数「第 N 页」) / 已完成 ✓(显示「N个·P页·Xs」) / 没定位到 ✗。
  - **异常标注**：收到 0 个 → ❗；翻页数 < 本轮平均 50% → ⚠（主指标是**翻页数/工作步数**，不是时长——时长受冷却影响不稳）。
  - **漏斗明细**。
- **岗位列表**：按公司分组，**默认全部收起**，点公司名展开。
- **精筛**：岗位词拆子词（AI产品经理→AI产品/产品经理/AI经理）或门 + 「其他」桶（默认不点）+ 每标签标数量。
- **75保护**（精筛区开关，默认开）：全选/自动全选封顶 75（`SOFT_BATCH_LIMIT`），关掉可超过。
- **导航箭头**：表头 `[←] 闪投 [→]`，→ 在条件页有结果时回结果页。
- **停止**：只停不重置，点击立刻刷新；回结果页入口（`hasResult`）。

## 4. 架构要点（别改坏）

- **三个 world**：panel ↔ service-worker（无 cookie，编排）↔ content.js(ISOLATED，消息路由) / collector.js(ISOLATED，复放请求/读DOM) / sniffer.js(MAIN，hook 页面 fetch 捕请求模板)。MAIN↔ISOLATED 只能 postMessage。
- **SW 不用 module 模式**（`importScripts` 共用一份 constants.js）。
- **长任务发令即返回**：`START_RECALL`/`START_GREETING`/`START_SEND` 立刻回 `{started:true}`，进度/收尾全靠 `TASK_PROGRESS` 广播。谁写成 `await run...()` 再响应，会因 SW 被回收或通道关闭卡死面板。
- **SW 保活**：长任务期间 `startKeepAlive()`/`stopKeepAlive()`（alarms 每 30 秒），否则 MV3 的 SW 空闲 ~30 秒被回收、任务卡住。`runRecall`/`runGreeting`/`runSend` 都挂了。
- **硬约束**（constants.js / README）：拉 JD ≥3000ms、单批 75、单日 150、分数地板 60、禁投 0-7 点。

## 5.5 埋点与使用统计（2026-10-06 新增）

需求方要求「只保三个数据」：①使用日活 ②海投/精投点击渗透 ③一键投递点击渗透。

- **实现**：`src/shared/tracker.js`（仅 panel 加载）。3 类事件：`panel_open`（日活）、`mode_click{mode}`（海投/精投 pill 点击）、`send_click{via}`（一键投递）。
- **口径**：渗透 = 点过该按钮的去重匿名 ID 数 ÷ 同期日活（去重 `panel_open` uid）。匿名 ID 首次运行生成，存 `ui:installId`，不含个人资料。
- **储存（方案 A·本地后台）**：事件数组存 `chrome.storage.local['ui:analytics']`，封顶 5000 条 FIFO（`CONFIG.ANALYTICS_MAX_EVENTS`）。
- **查看**：条件设置页底部「使用统计」折叠区，显示今日日活 + 近 30 天三项渗透，可导出近 90 天逐日 CSV（带 BOM）。
- **方案 B 预留**：`CONFIG.ANALYTICS_ENDPOINT` 配上云端地址后 `flush()` 自动批量上报（游标 `ui:analyticsUploaded`），埋点侧零改动。
- **铁律**：`track()` 任何异常都静默吞掉，埋点永不影响搜索/投递主流程。

## 5.6 数据后台页 + 客服反馈（2026-10-06 新增，需求 #5/#7）

对齐《周五上线需求》：#7 数据后台 = 口令保护的只读页（v1 不做账号/权限）；#5 客服反馈入库。

- **后台页**：`src/admin/admin.html|css|js`。入口在客服抽屉底部「数据后台（内部入口）」链接，新标签打开。
  - 口令：首次打开自设（≥4 位），存 SHA-256 哈希于 `ui:adminPass`（不存明文）；认证态只在内存，关页重输；忘记口令只能清扩展数据。
  - 内容：核心三指标卡（今日日活 + 近 30 天三项渗透）、逐日明细表、客服反馈列表；两个导出 CSV（埋点近 90 天 / 反馈全量，均带 BOM）。
  - 只读：页面没有任何写操作（除首次设口令）。
- **客服反馈**：客服抽屉（panel.html service-drawer）FAQ 下方新增表单。字段 = 自由文本(必填) + 联系方式(选填) + 自动带版本号(manifest)/来源页(S.screen)/时间/设备 ID(Tracker.uid)。存 `ui:feedback` 数组，封顶 500 条 FIFO（`CONFIG.FEEDBACK_MAX`）。提交不影响主流程，失败 toast 提示。
- 后台页**不**调 `Tracker.track`——查看后台不算日活。
