## 0. 一句话现状

闪投 = BOSS 直聘 Chrome MV3 扩展（侧边栏）。两模式：
- **海投（position）**：布置改网址版——分页数=地点×职位词，一词一城一个分页**直接开全条件 URL**（`/web/geek/jobs?city=&query=&全部筛选参数`，用户 2026-10-08 实测样本定参数名/码表）→ **滚动读卡**，一次滚动=一个行为，行为闸 3~4 秒。
- **精投（company）**：锁定几家公司，进**每家公司招聘页读 DOM 卡**收岗位，全局行为节流。

全链路可跑：搜索召回 → 就地生成招呼语 → 投递。核心精力都花在**精投的可靠性 + 节流**上。

`secrets.js`（通义千问 key）走 `.gitignore`，各人 `cp src/shared/secrets.example.js src/shared/secrets.js` 填自己的。

## 1. 精投现在怎么工作（重点，最近全重写过）

**入口**：`service-worker.js` 的 `augmentFromCompanyPages(merged, config, onProgress)`。

### 1.1 搜索时长与行为预算
- 设置齿轮里有「搜索时长」拉杆：**3~30 分钟**，存 `chrome.storage['jt:searchMinutes']`，默认 5。
- 后台：`taskTimeoutMs = 分钟×60000`（时间硬上限）；`actionsBudget = 分钟×17`（`ACTIONS_PER_MINUTE`，每分钟 17 个行为，因为全局每 ~3.5 秒一个行为；5 分钟 ≈ 85 个。2026-10-06 定 12，10-08 随闸提速同步改）。

### 1.2 全局行为闸（turnGate）——节流核心
- **全局每 3~4 秒随机才放行一个「翻页行为」**（读一页 = 一个行为，用户 2026-10-08 由 4~6 改 3~4，与海投一致），用「预约下一个时间槽」(`nextTurnAt`) 保证并发的页面依次拿槽（先到先得≈轮流派发），不会一起放行。
- 任意时刻只有一个请求在飞、均匀无突刺，这是躲限流(code:37)的关键。
- `actionsDone` 每放行一次 +1；进度条 % = `actionsDone / actionsBudget`（面板不显示数字，只显示 %）。
- 到 `taskDeadline`（时间上限）或全部收完就停。

### 1.3 一条龙 per 单元（onePass，2026-10-08 真人链路微重做）
**单元 = 公司 × 城市 × 岗位词（用户 2026-10-08 定），一个单元开一个分页**：布置这一个城市 + 搜这一个词。
- 全国/没选城市 → 只有一个不带城市的单元（城市维度跳「全部」，本地过滤兜底）。
- **一个分页从头到尾开一次、关一次**（用户定）：中间全靠页内点击导航，不中途换分页。
- 同一家公司的多个单元**各走全流程**（不缓存定位结果，用户 2026-10-08 定）。
- 面板耗时预估同步：单元数 = 公司数 × 城市数 × max(词数,1)（`estimateUnits`）。
- （恢复搜索断点已随该功能整体取消，2026-10-08）

每个单元一条龙跑完（真人链路，用户 2026-10-08 用截图逐页定的）：
1. **开首页分页**（`zhipin.com/?ka=header-home-logo`）→ 搜索栏打公司搜寻名点搜索（`DRIVE_HOME_SEARCH`）。
2. **点卡**（`COMPANY_CLICK_CARD`，collector.clickCompanyCard）：结果页读一排卡片左下角的公司名，
   点最贴合的一张进公司页；点击前去掉链接 `target`，保证同分页内跳转。页内轮询等卡片渲染（最多 ~16 秒）。
3. **核对页头**（`READ_COMPANY_HEADER` 轮询）：公司页页头公司名与目标名互含才算进对门；
   **不吻合 → goBack 回结果页试点次优的卡，最多 3 张**（用户定），仍不吻合记「没定位到」。
4. **改网址一次到位**（2026-10-08 用户定稿，点招聘职位/搜词/布置合一）：核对页头通过后从当前
   URL 抽 brandId（贴网址分支直接用 override），拼最终 URL 一次 `tabs.update`：
   `/gongsi/job/[c{城市码}/]{brandId}.html?query={词}&salary={码}`（无参数时带 `?ka=company-jobs`，
   跟人点 tab 一样）→ `COMPANY_JOBS_READY` 轮询就绪（没就绪 → 该单元按没定位到交回重做）。
   旧的 `COMPANY_CLICK_JOBS_TAB`/`COMPANY_BOX_SEARCH`/`COMPANY_BOX_ENSURE` 保留不删不再调用。
5. **翻页扫卡收答案**：`COMPANY_DOM_PAGE` 一页页读（每页前过 `turnGate`），到 底/页数上限/无新增/收够/份额用完 停。
- **关键渲染步骤前把分页激活到前台**（首页搜索/点卡/核对/改网址）：BOSS 列表是 SPA，后台标签被渲染节流会读不到卡（腾讯栽过）。翻页扫卡阶段后台已验证没问题。
- 用户**贴过公司主页网址**的（`brandOverrides`）：跳过首页搜索/点卡/核对，直接拼职位页 URL 一次导航到位。

### 1.4 并行池 + 行为预算平分（2026-10-08 用户定）
- **并行上限 8 个分页**：`P = min(PARALLEL_COMPANIES=8, 单元数)`，一个分页收完立刻从队列拉下一个单元顶上。
- **总行为数平分给每个单元**：`perUnitBudget = max(2, floor(actionsBudget / 单元数))`（不足 2 保底 2 = 读一页+翻一页）。
  每个单元只数自己的 `unitActions`，花完份额这个分页收工（diag 记「单元行为份额用完」）；全局 turnGate 照旧管节奏（份额是上限不是配速）。
- **没定位到的单元重做**（用户 2026-10-08 定）：`processUnit` 里 `!r.located` → 最多重做 3 次（隔 1~3 秒随机，跟人重试一样），每次重做 `actionsBudget += 10` 且该单元 `cap += 10`（总剩余行为数 +10，这份留给重做的单元自己用）；diag 记「没定位到，第N次重做（总预算+10）」。每次尝试的分页在 onePass 的 finally 里关掉，重试开新分页。
- 旧的「行为数 ≤4 整家重做 + 预算+10」逻辑随单元化**取消**：单元粒度小，一两页收工是正常结局（定位成功的单元不重做，提前收工的份额走回流）。
- 公司级汇总（面板按公司展示）：`remainBy` 记每家剩余单元数，全部跑完才落「已完成/没定位到」终态；stats 的用时/页数跨单元累加；`companySeen` 一家多单元共用（收够 perCompanyCap 就停翻）。

### 1.5 开页节流 + 关标签（模块级共享，精投/海投同一套）
- `acquireOpenSlot()`：每开一个分页全局隔 1~2 秒随机（预约槽，并发也真错开）。精投开公司标签、海投开城标签都过这同一条闸。
- `closeTabLater(tabId)`：用完的标签**延迟 1~3 秒随机再删**，且**后台异步不阻塞**（下一个不等删完就开始）。
- 间隔常量集中在 `constants.js`：`TAB_OPEN_MIN/MAX_MS`(1000/2000)、`TAB_CLOSE_MIN/MAX_MS`(1000/3000)。
- **长期原则（用户定的）：这类行为要模仿人类**——人不会同一秒连开 5 个分页、不会用完瞬间关掉、每一步操作前都会看一眼页面。以后加分页/导航/点击类行为，一律走共享闸 + 随机区间停顿，不写死固定值。

- **改搜索词（改搜寻名）功能已撤**（2026-10-08 用户定：「任务失败后就不用让用户改搜索词了」）——
  失败后走贴网址/列表，`S.searchOverrides`/`jt:searchOverrides`/`.cs-edit` 按钮全删；旧存储键残留无害不再读。
- **boss公司頁網址列表**（2026-10-08 用户定，`src/shared/company-urls.js`）：公司名/别名 → 公司页网址，
  精投定位**先查表再搜索**。命中 → 跳过首页搜索/点卡/核对直达；没命中 → 走搜索全流程。

  `companyUrlLookup` 去空白+小写后全等比对（不互含，防短名误命中）。diag 记「定位:boss公司頁網址列表命中，直达」。
- **列表网址统一用「招聘职位页」形态**（2026-10-08 用户定）：`/gongsi/job/{brandId}.html?ka=company-jobs`
  （简介页形态也认，推荐职位页）。命中后直接开职位页核对页头（`BOSS.PAGE.COMPANY_JOBS`，省「简介页→职位页」
  一次导航）；随后拼最终 URL 时若与当前 URL 一致（无词无薪资无城市码）就**不再重复导航**，直接就绪轮询开扫。

  回到搜索的方式搜**）：贴的/列表里的 brandId 打不开或页头指向别家时，diag 记

## 2. 海投现在怎么工作（2026-10-08 重做：布置改网址版）

海投 v2 入口是 SW 的 `runHaitouScroll(config, merged, onProgress)`。**2026-10-08 用户实测拍板：复数 `/web/geek/jobs` 页吃全部 URL 参数**（用户逐维抓样本：city/query/multiBusinessDistrict/position/jobType/payType/partTime/salary/experience/degree/industry/scale/stage），布置不再开主页打字、不再点任何筛选——**一词一城一个分页直接开全条件 URL**：

1. **一词一城一个分页**（分页数 = 地点数 × 职位词数；最多 `HAITOU_MAX_TABS: 5` 并行、其余排队），开分页前过布置闸（`layoutSlot()` = `acquireOpenSlot(HAITOU_LAYOUT_*)`，1~2 秒随机）——几个分页轮流开；采完经 `closeTabLater()` 隔 1~2 秒随机再关。
   - 目标 URL 由 SW `buildSearchUrl({ query, city, ...filters })` 一次拼好：**词=`?query=`、城市=`?city=码`、全部筛选条件同参带上**，多选逗号拼接（用户实测：选九个区就是九个码逗号连），**不限 = 不带该参数**。
   - **参数名/码表按用户 2026-10-08 实测样本**：区域参数是 `multiBusinessDistrict`（旧代码拼的 `businessDistrict` 页面不认，区域条件从没通过 URL 生效过）；`salary=402~407`、`experience=101~108`、`degree=202~209`、`scale=301~306`、`stage=801~808`、`jobType=1901全职/1903兼职`、`industry=100020…`、`payType=2501~2504`、`partTime=2701~2706`（payType/partTime 面板还没有，构造器先透传）。
   - **工作区域 BOSS 限选 9 个**（用户实测）：超出截前 9 个并 warn 上报；区名（没抓到真 code 的）塞 URL 没意义，只带数字 code。**公司行业副选限 3 个**（用户 2026-10-07 告知）：截前 3 个 + warn。
   - 面板内置码表同步按样本修正：`experience` 旧表整体错位（正确：在校生=108/应届生=102/经验不限=101/1年以内=103/1-3年=104/3-5年=105/5-10年=106/10年以上=107）、`jobType` 兼职=1903（旧表误写 1902；实习=1902 未实测）。
   - 取证：每个单元开页后把布置 URL 解码落 Console（`[闪投] 海投布置URL:`）——参数在 → 导航成了；没生效就是 BOSS 没认参数。
   - 点击版布置整套退役：`APPLY_CITY`/`APPLY_FILTER`/`READ_CITY_CHIP` 的 content 处理器**留档不删不再调用**（同 realClick 先例）；`DRIVE_HOME_SEARCH` 精投仍在用，不受影响。
2. **滚动读卡**（`COLLECT_ONE_SCROLL` 单步，collector.collectOneScroll）：读新增卡 → 滚一屏 → 等渲染再读。**一次滚动 = 一个行为**，过模块级全局闸 `acquireTurnGlobal(3000, 4000)`——**海投 3~4 秒随机**（`HAITOU_TURN_GATE_MIN/MAX_MS` 与精投 `TURN_GATE_MIN/MAX_MS` 各自独立可调，2026-10-08 起精投同为 3~4）。
   - 链路各步**停留一律 0.5~1 秒随机**：页面加载后看一眼、激活标签后滚动前。
   - 新版结果页是「左卡右 JD」双栏，左栏滚动加载；滚动懒加载**只在前台标签触发**（后台被 Chrome 节流），所以每步滚动前把标签**轮换激活**——跑海投时几个标签会轮流跳前台，正常现象。
   - **字段补全**：DOM 卡只有卡片字段，读卡后拿 jobId 查嗅探器的 `JOBLIST_META` 补接口级字段（HR 活跃度、公司规模、融资阶段等）——行为是人的，字段是接口级的。
   - **薪资防乱码**：BOSS 薪资数字用自定义字体渲染，DOM 读出来是私有区字符。collector 用 `GARBLE_RE` 检测，乱码就丢弃 DOM 值、用嗅探器从接口 JSON 抓的 `salaryDesc` 兜底。
3. **中止条件（用户 2026-10-07 定）：3 分钟 / 150 个结果 / 60 个行为，任一先到即停**（`HAITOU_STOP_MINUTES/HAITOU_MAX_RESULTS/HAITOU_MAX_ACTIONS`）；60 个行为按「词×城」单元平分，连续 3 次滚动 0 新增（滚到底）该单元提前收工。布置改网址后每单元只剩「开分页」一个布置动作，60 个行为几乎全用在滚动收卡上。搜索时长拉杆对海投不再生效（精投不受影响）。
4. 进度复用精投的 `actionsDone/actionsBudget` 口径，面板 % 显示同源。

旧的「接口复放 + 多城各自本地 sleep」路径（collectOnCity）已删除。`COLLECT_PAGES` 路由和 `collectPages` 保留（精投定位、DOM 兜底仍在用）。

## 4. 架构要点（别改坏）

- **三个 world**：panel ↔ service-worker（无 cookie，编排）↔ content.js(ISOLATED，消息路由) / collector.js(ISOLATED，复放请求/读DOM) / sniffer.js(MAIN，hook 页面 fetch 捕请求模板)。MAIN↔ISOLATED 只能 postMessage。
- **SW 不用 module 模式**（`importScripts` 共用一份 constants.js）。
- **长任务发令即返回**：`START_RECALL`/`START_GREETING`/`START_SEND` 立刻回 `{started:true}`，进度/收尾全靠 `TASK_PROGRESS` 广播。谁写成 `await run...()` 再响应，会因 SW 被回收或通道关闭卡死面板。
- **SW 保活**：长任务期间 `startKeepAlive()`/`stopKeepAlive()`（alarms 每 30 秒），否则 MV3 的 SW 空闲 ~30 秒被回收、任务卡住。`runRecall`/`runGreeting`/`runSend` 都挂了。
- **硬约束**（constants.js / README）：拉 JD ≥3000ms、单批 75、单日 150、分数地板 60、禁投 0-7 点。

## 5.5 埋点与使用统计（2026-10-06 新增）

需求方要求「只保三个数据」：①使用日活 ②海投/精投点击渗透 ③一键投递点击渗透。

- **实现**：`src/shared/tracker.js`（仅 panel 加载）。3 类事件：`panel_open`（日活）、`mode_click{mode}`（海投/精投 pill 点击）、`send_click{via}`（一键投递）。
- **口径**：渗透 = 点过该按钮的去重匿名 ID 数 ÷ 同期日活（去重 `panel_open` uid）。匿名 ID 首次运行生成，存 `ui:installId`，不含个人资料。
- **储存（方案 A·本地后台）**：事件数组存 `chrome.storage.local['ui:analytics']`，封顶 5000 条 FIFO（`CONFIG.ANALYTICS_MAX_EVENTS`）。
- **可见性（2026-10-07 用户定）**：使用统计**不给用户看**——面板「使用统计」折叠区已下线（HTML/JS 移除）；数据是公司看的，查看走密码保护的数据后台（§5.6）。
- **储存与传送（2026-10-07 用户定「想办法储存和传送」）**：事件落 `chrome.storage.local`（封顶 5000 FIFO）；service worker **每 6 小时 + 每次启动自动 `Tracker.flush()`** 批量上报（alarm `analytics-flush`）。`CONFIG.ANALYTICS_ENDPOINT` 配上云端地址即生效，未配置时空转只存本地；成功才推进游标 `ui:analyticsUploaded`，失败静默下轮再传。
- **铁律**：`track()` 任何异常都静默吞掉，埋点永不影响搜索/投递主流程。
