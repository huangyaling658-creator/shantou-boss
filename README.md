## 安装

1. Chrome 打开 `chrome://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选中本目录
4. 点扩展图标打开侧边栏

## 使用（M0 能做到的）

1. 浏览器里打开 BOSS 直聘，**确保已登录**
2. 进岗位搜索页，在 BOSS 自己的界面上设好筛选条件并搜索一次
3. 打开闪投侧边栏 → 配置页 → 点「开始召回」
4. 采集完成后到「审核」页看抓到的岗位

M0 阶段的筛选条件完全沿用你在 BOSS 页面上的设置。公司白名单、匹配度打分、招呼语、投递都还没做。

## 代码结构

```
manifest.json
src/
  shared/
    constants.js      消息类型 / 存储键 / BOSS 接口 / 运行参数 / 状态机
    utils.js          岗位名归一化、指纹、Jaccard、并发控制
  db/
    repository.js     IndexedDB 数据层（走接口抽象，留了上后端的迁移口子）
  content/
    sniffer.js        MAIN world，hook 页面自身请求，捕获列表请求模板
    collector.js      ISOLATED world，复放分页请求、拉 JD、解析品牌
    content.js        消息路由
  background/
    service-worker.js 任务编排、标签页管理、去重入库
  panel/
    panel.html/css/js 侧边栏界面
```

### 三个关键设计

**1. SW 不用 module 模式**

manifest 里刻意没写 `"type": "module"`，为的是能用 `importScripts()` 加载与 content script 完全相同的那份 `constants.js`。竞品即投因为用了 module，常量必须在两处各抄一份，代码里到处是「🔴 必须镜像 selectors.js」的警告，一处漏改消息就静默发不出去。一份源码两边共用，从根上没有这个问题。

**2. 不自己拼搜索 URL**

BOSS 的列表请求带一批无法稳定复现的参数（securityId、场景标识、随改版增减的查询串）。自己拼当天能跑，平台一改就静默失效，而失效的表现是「搜到的岗位变少」，不报错，极难发现。所以 MAIN world 嗅探器捕获页面自己发出的真实请求当模板，只替换 `page`。

**3. 直调接口而不是滚动加载 DOM**

Chrome 对后台标签页有引擎级节流，BOSS 的无限滚动懒加载不触发，只能拿到首屏十几条。网络请求不受可见性节流影响，所以直调接口是唯一能在后台稳定跑满的路径。

## 硬约束（改代码时别碰）

| 约束 | 值 | 原因 |
|---|---|---|
| 拉 JD 间隔 | ≥ 3000ms | 实测 1.5s 触发 BOSS 软封锁 `code:37` |
| 单批投递上限 | 75 | 留出余量，不顶平台约 100 次的天花板 |
| 单日累计红线 | 150 | |
| 分数地板 | 60 | 低于此宁可投不满也不投，否则退化成海投 |
| 禁投时段 | 0 到 7 点 | 凌晨批量操作特征太明显 |

## 风险提示

抓取与自动投递违反 BOSS 直聘用户协议，存在账号被限流的风险。平台第一层惩罚是弹验证码而非封号，本工具探到边界即停、不硬顶。当前版本自用。
